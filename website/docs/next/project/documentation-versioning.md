# Documentation versioning

The website/docs/next/ tree is the **Next** manual for current 2.x development. Its route is /evolvephp/next/, and it carries the pre-release status and limitations. No historical version is generated by this first documentation milestone.

The 2.0.0-alpha.1 release predates much current 2.x work. Snapshotting today's Next pages and naming that tree 2.0.0-alpha.1 would misrepresent the release. Historical backfills must be written from the actual tag's implementation, tests and release evidence.

For a future release, first review the documentation against the actual release tag, its implementation, tests and release records. Copy the verified release-specific pages into a new immutable snapshot directory under website/docs/versions/ only when a snapshot is useful. Name prerelease snapshots for their real released identity; stable documentation normally follows the minor line, such as 2.0 or 2.1. Current development remains Next. Record the source tag or commit for every snapshot in its landing page and review all cross-links.

MkDocs has no version selector in this proposal. Add navigation to a snapshot only after that snapshot is reviewed. A version label is a documentation navigation aid; it does not itself establish package compatibility or support.

## Source links for frozen versions

The Next site's Edit links point to the moving 2.x branch. For each frozen release, set its source and edit links to the matching immutable release tag or commit, or omit an edit link if the selected theme cannot represent a per-version edit reference accurately. Do not treat a copied tree alone as release evidence.
